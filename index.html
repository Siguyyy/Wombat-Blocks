Robot setup

Enter measurements from your assembled robot. The build guide shows the claw linkage but gives no finished reach dimensions. Chassis width and wheel track are different: track is wheel-center to wheel-center. The preview uses 1.5 cm tire width, so outside tire span is track + 1.5 cm.

Measured drive behavior

Servo presets and claw model · estimates

Calibrate left and right pivots independently: new scale = current scale × commanded angle ÷ measured angle. Example: 180° commanded, 165° observed → multiply the scale by 180/165. Verify direction with a 90° pivot; a 180° turn cannot show whether it turned left or right.

Measure the single arm from its chassis hinge to the claw mount, and measure the arm beam width. The build guide does not specify these finished dimensions; preview defaults are estimates. When raised, the arm is foreshortened in the top view; set Arm UP top-view reach to the fraction still visible from above. The claw crossbar and jaws stay attached at the arm tip. This is a visual estimate, not a height or torque model.

Drive a measured straight distance on the competition surface and adjust each side scale from observed travel. Recheck under normal payload. Encoder feedback cannot correct wheel slip, floor changes, or varying battery condition.

Wombat Blocks

  1. Drag a block from the toolbox into the workspace. Connect it to the start block. Use Restore start block if it is missing.
  2. Stack blocks to move a whole routine. Use Repeat to contain reusable action sequences.
  3. The map uses centimeters from the robot's starting point: X is right, Y is forward. A point 10 cm left and 30 cm ahead is X −10, Y 30.
  4. Type coordinates and dimensions to place an obstacle exactly. Select and drag it to adjust position, or edit its X/Y/size below the map.
  5. The robot position readout follows the preview. Stock drive defaults match ports 0/1 and about 800 ticks/s at 100%; measure and calibrate your own robot before relying on turns. Adjust the single arm length, beam width, and claw opening in Robot setup.
  6. Distance blocks use the measured speed and support encoder-controlled MAV or motor PWM. A direct motor block takes signed MAV ticks/s or motor percent; use Stop afterward.
  7. Sensor blocks use Wombat analog ports 0–5 and digital ports 0–9. Analog sensors include reflectance/tophat, light, rangefinder/ET, and slide sensors; digital inputs include lever and touch switches. Which sensor uses each port depends on your wiring.
  8. Camera blocks require a connected camera and configured KISS color channel. Sensor branches, camera results, and direct motor commands are hardware-only: the map preview cannot know live readings or predict these actions.
  9. Output includes beep and console logging. Use View generated C to inspect the full KIPR file. Run on robot connects to the Wombat, overwrites the selected project main.c, compiles, and starts the physical robot.

Run on a Wombat

Connect this computer to the Wombat's Wi‑Fi, enter its IP, then select a KISS user and a dedicated C project.

Running replaces the selected project's src/main.c with the generated C, compiles it, and starts it on the physical robot. Create a dedicated C project for Wombat Blocks first. Use only on your robot's trusted Wi‑Fi.
