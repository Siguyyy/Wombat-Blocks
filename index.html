Turn and drive correction changes the block labels, dropdown choices, and simulator direction. It preserves the stored direction values, so existing generated motor commands keep their original behavior.

The simulator treats a pivot as an ideal in-place rotation by the requested angle. These left/right calibration scales affect generated robot C only. Calibrate each side independently: new scale = current scale × commanded angle ÷ measured angle. Example: 180° commanded, 165° observed → multiply the scale by 180/165. Verify direction with a 90° pivot; a 180° turn cannot show whether it turned left or right.

Measure the single arm from its chassis hinge to the claw mount, and measure the arm beam width. The build guide does not specify these finished dimensions; preview defaults are estimates. When raised, the arm is foreshortened in the top view; set Arm UP top-view reach to the fraction still visible from above. The claw crossbar and jaws stay attached at the arm tip. This is a visual estimate, not a height or torque model.

Drive a measured straight distance on the competition surface and adjust each side scale from observed travel. Recheck under normal payload. Encoder feedback cannot correct wheel slip, floor changes, or varying battery condition.

Wombat Blocks

  1. Drag a block from the toolbox into the workspace. Connect it to the start block. Use Restore start block if it is missing.
  2. Stack blocks to move a whole routine. Use Repeat to contain reusable action sequences.
  3. The map uses centimeters from the robot's starting point: X is right, Y is forward. A point 10 cm left and 30 cm ahead is X −10, Y 30.
  4. Type coordinates and dimensions to place an obstacle exactly. Select and drag it to adjust position, or edit its X/Y/size below the map.
  5. The robot position readout follows an ideal preview: pivots rotate exactly by the requested angle. Left/right pivot calibration applies only to generated robot C; measure and tune it on your robot. Adjust the single arm length, beam width, and claw opening in Robot setup.
  6. Distance and pivot blocks use the 1.12 preview encoder-feedback controller with calibrated targets. The separate two-wheel distance block lets each wheel use its own MAV speed percentage. Mark/retrace blocks reset drive encoders and reverse recorded drive/pivot steps. The direct motor-position block still offers mrp and mtp. Direct motor blocks support MAV ticks/s or motor percent; use Stop afterward.
  7. Sensor blocks use analog ports 0–5 (raw 0–4095) and digital ports 0–9. Analog sensors include reflectance, light, range, and slide sensors; digital inputs include lever and touch switches. A raw analog value is not centimeters until you calibrate that exact sensor. Analog port profiles apply an empty-reading band, stable median filtering, and confirmation to existing sensor decisions.
  8. Configure analog empty-reading bands per port in Robot setup. Existing analog conditions, waits, repeat-until, and drive-until blocks use that profile automatically; raw logs and samples are unchanged.
  9. Use the Sensors block physical controller button pressed? in an if, while, or wait-until condition. It reads the built-in side button via KIPR push_button(); the web simulator has no physical button and returns false.
  10. Control includes a simple if and stackable else-if blocks. Stack else-if blocks after a simple if. Comment blocks may sit between clauses; waits or other actions break the chain. The original if/else block remains available for older projects.
  11. Operators can combine sensor readings. While, do-while, repeat-until, and wait-until blocks have timeouts; timeout failure stops motors and exits the program. Drive until analog stops both drive motors automatically when its threshold is crossed.
  12. Camera blocks require a connected camera and configured KISS color channel. Sensor branches, camera results, direct motor commands, and the map preview cannot know live readings or predict these actions.
  13. Repeat forever runs an action stack until the Wombat side button is pressed or an explicit stop-program block runs. Console drive commands use the KISS program console: w/b move, a/d pivot, s stop, r toggle and announce gear, o/c open/close the claw, p/l raise/lower the arm, q exits the prompt. Console input and wait-for-light cannot be interrupted by the side-button stop.
  14. Output includes beep and console logging. Use View generated C to inspect the full KIPR file. Run on robot connects to the Wombat, overwrites the selected project main.c, compiles, and starts the physical robot.
